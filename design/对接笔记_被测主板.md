## 1. 被测板工程概况

- 与治具框架同源（uCOS-II + 标准库），但功能完整：FOC 双电机驱动、MPU60x0 姿态、2.4G 遥控（NRF24L01）、显示/手柄板通信、BMS、EEPROM 参数、IAP 升级
- 机型配置示例（main.h，`MODE_KS_DUAL_N07TESTgdB`）：机型码 `ZZ-DW`，软件版本 `0117`
- **关键文件**：
  - `app/selfcheck.c/.h` —— 产线自检（电机测试核心，治具 M1/M2 的原型）
  - `app/appfun.c` —— APP 协议命令解析（`USART_USER_IRQ_APP`）
  - `Motion/pack/ComPackPro.c` —— 协议分发，串口映射
  - `Motion/pack/usartset_u4.c` —— UART4 驱动（DMA + IDLE 中断）

## 2. 对接串口（治具 CN8 ↔ 被测板）

| 项目 | 值 |
|---|---|
| 物理口 | **UART4**（`DSPLAYBOARDTYPE==0` 时 APP 协议固定在 UART4） |
| 波特率 | **115200**，8N1（bsp.c 只初始化了 u4） |
| 帧长 | **固定 20 字节** |
| 同口承担 | APP 协议命令、周期数据上传、自检触发、自检结果上报 |

### 2.1 帧格式（收发同格式）

```
偏移    0     1     2........15      16        17          18    19
      ┌─────┬─────┬──────────────┬─────────┬───────────┬─────┬─────┐
      │0xAA │0x5A │ 7×s16 小端数据 │ 包类型CMD│ 校验      │0x5A │0x55 │
      └─────┴─────┴──────────────┴─────────┴───────────┴─────┴─────┘
```

- 校验 = `(字节0~16 累加和) ^ 0xFF`
- 例外：CMD 为 0x44 / 0x61 / 0x70 的帧不做校验检查（bootloader 相关）
- ⚠ 自检结束帧 `{AA 5A C9 00...00 1C 16 5A 55}` 的 [17]=0x16 与累加和算法对不上，疑似该帧用了 CRC16——**联调时以实测为准**

### 2.2 命令表（治具 → 主板，CMD = 帧[16]）

| CMD | 功能 | 附加条件/数据 | 主板应答 |
|---|---|---|---|
| 0x9B | 读机型/版本 | — | 帧[16]=0xBB，数据区含 ASCII 机型+版本（如 `ZZ-DW-0117`）；**此后主板开始周期上传（senddata_sw=1）** |
| 0x88 | 蜂鸣器测试 | — | 蜂鸣器短响一声 |
| **0x1C** | **触发自检** | 帧[2]=0xC9，且车速=0 | 启动 selfcheck 流程（见 §3） |
| 0x65/0x66 | 参数恢复默认 | — | 蜂鸣确认 |
| 0x70 | 跳 bootloader | 帧[17]=0x8B/0x14/0x15 时执行跳转；0x21/0x22、0x41/0x42 查询 | 固定应答帧 |

> 隐藏调试通道：先发送 `55 AA 0E 0B ED 00 01 02 03 04 05 06 07`（DEBUG_SW_KEY）进入 vartab 调试模式，之后走 `55 AA + 长度 + 数据 + CRC16` 的调试协议，可读写内部变量——**治具如需要读表里没有的量，可考虑这条路（联调阶段验证）**。

### 2.3 周期上传包（主板 → 治具，CMD = 帧[16]，发 0x9B 后启动）

| CMD | 通道内容（ch1~ch7，s16 小端） |
|---|---|
| 0xA9 | ch1=总电压(V×100) ch2=车速(km/h×100) ch3/4=总里程 ch5=总电流(A×100) ch6=MOS温度(℃×100) ch7=模式 |
| 0xB9 | 当前里程/运行时间/最大速度/电池状态/电机温度 |
| **0xF5** | **报警状态**：高温、电机错误、霍尔错误、传感器错误、CPU 占用、母线电压比例 |
| 0xF6 | 限速值、ODO 时间、报警索引 |

> 注意：**自检期间周期上传暂停**（`commsendapp()` 直接 return 0）。

## 3. selfcheck 自检流程（治具电机测试的原型）

### 3.1 触发与约束

- 触发：UART4 收到 0x1C 命令帧且帧[2]=0xC9、车速为 0
- `selftestflgcnt` 被置 2200，motion 主循环在其 >2100 的窗口内进入 `MOTION_SELFCHECK`——**触发后约 100 tick 内有效，治具超时未测完需重新触发**
- 前提：非充电、非急停状态（motion 状态机约束）

### 3.2 状态机步骤（`selfcheckrunning()`，motion 周期调用）

| 步骤 | 动作 | 判定（限值见 §4） |
|---|---|---|
| SELFCHK_WAIT | 等 200 tick 稳定，采零偏：母线电流零偏、两电机三相注入 ADC 零偏 | 各零偏 ≤2600 |
| SELFCHK_CHK_VOL | 测 CPU 电压、母线电压 | cpuvol 3000~3600mV；allvol 20.0~46.0V |
| SELFCHK_CHK_FOC0 | FOC 使能、Vq=0（DEBUG 模式） | 总电流/各相电流 ±200（≈±2A） |
| **SELFCHK_CHK_FOCa/b/c** | **强制电角度 0°/+120°/−120°，Vq=2800，转子吸附锁定，EMA 滤波采集对应相电流** | 三相吸附电流：六相均值 >1000（≈10A），且每相在均值的 2/3~4/3（对称性判缺相）；总电流 1000~1800 |
| SELFCHK_CHK_FOCdrv | 强制驱动转动（hdrvflg=4，Vq=2800） | 等霍尔三路信号全部翻转过（mark L 清零、H 集齐 0x07），2000 tick 超时 |
| SELFCHK_CHK_SPacc | Vq 从 0 斜坡升到 4000（+20/tick） | 霍尔速度 100~2000 |
| SELFCHK_CHK_SPrun | 稳速运行 400 tick 后停 | 霍尔 mark 复核 + 霍尔错误计数 ≤1 |
| SELFCHK_CHK_HANDLE | MOS 温度、遥控通信计数 | MosTemp 10~32℃；**commu_cnt ≥10（遥控在线）** |
| SELFCHK_CHK_OTHER → REPORT | 逐项上报结果 | 见 §3.3 |
| SELFCHK_CHK_END | 蜂鸣长响一声，发结束帧 | — |

### 3.3 结果上报格式（主板 → 治具）

- 每项一行，**20 字节文本帧**：`[12 字节 ASCII 名称][数值 %d][失败时附 "X"]`，每 10 tick 发一项
- 全部报完后发**结束帧**：`AA 5A C9 00×13 1C 16 5A 55`
- 上报出口：默认 UART4；若被测板编译时定义 `SELFCHECK_JIG_ENABLED` 则改走 2.4G（`selfcheck_rf_send`）——**本治具走有线 UART4，不需要该宏**

## 4. 结果数据结构（`CSELFCHECKRESAULT checkresault[]`）

```c
typedef struct {
    u8  ckpassflg;      // 通过标志
    u8  ckcnt;          // 持续达标计数（静态项需 200 次、短项 20 次）
    s32 ckval;          // 实时值
    s16 reportval;      // 上报值（锁定在达标瞬间）
    s16 thr_l, thr_h;   // 上下限
    u8  checkname[12];  // 项名称
} CSELFCHECKRESAULT;
```

### 4.1 测试项索引与门限（双电机，括号内为序号）

**电机0（左）：** ic_a0_os(0) ic_b0_os(1) ic_c0_os(2) [0~2600] · ic_a0_L(3) ic_b0_L(4) ic_c0_L(5) [±200] · ic_a0_H(6) ic_b0_H(7) ic_c0_H(8) [对称性判定] · hal_mk_L0(9) [=0] hal_mk_H0(10) [=7] · hall_sp0(11) [100~2000] · hall_err0(12) [≤1]
**电机1（右）：** ic_a1_os~ic_c1_os(13~15) · ic_a1_L~ic_c1_L(16~18) · ic_a1_H~ic_c1_H(19~21) · hal_mk_L1(22) hal_mk_H1(23) · hall_sp1(24) · hall_err1(25)
**公共：** allvol(26) [2000~4600] · allcur_os(27) [1800~3600] · allcur_L(28) [±200] · allcur_H(29) [1000~1800] · mostemp_L(30) [10~32] · mostemp_H(31) [10~190] · cpuvol(32) [3000~3600] · com_cnt(33) [≥10]

> 使能开关（selfcheck.c 顶部）：双电机=开、CPU电压=开、通信计数=开；手柄/陀螺/IO/CAN=关

## 6. 治具测试项与被测板机制映射

| 治具项（方案 V0.3） | 被测板对应机制 |
|---|---|
| C2 版本读取 | 发 0x9B，收 0xBB 帧解析 ASCII 版本 |
| D1 主板自采电压 | 0xA9 帧 ch1（或自检 allvol 项） |
| D2 主板自采电流 | 0xA9 帧 ch5（或自检 allcur_L 项） |
| D3 报警状态 | 0xF5 帧各位 + selfcheck 的 hall_err 项 |
| M1a 三相吸附 | 自检 FOCa/b/c（Vq=2800，电角度 0/±120°） |
| M1b 空转（转速+空转电流） | 自检 SPacc/SPrun（hall_sp 项 + 0xA9 电流） |
| M2 霍尔采集 | 自检 hal_mk_L/H（0/7）+ hall_err ≤1 |
| M3 遥控连接 | 自检 com_cnt ≥10（测试时遥控器需在线发数） |

## 7. 治具侧实现注意点

1. **时序**：触发自检后主板侧全流程约 (200+200+400×3+2000+400+400+3000+100+100) tick 量级，motion tick 频率需确认（约 500Hz~2kHz），治具等待上报的超时建议 ≥15s
2. **解析策略**：现有上报是 20 字节文本行，治具可直接按名称匹配解析数值和 "X" 失败标记；**双方已确定定制专用协议（见 [治具对接协议_v1.0.md](治具对接协议_v1.0.md)，CMD=0xC8/0xC9，二进制结构化上报），主板侧仅需新增 jigpro.c/h 并在 appfun.c、selfcheck.c 打三个补丁点，隐藏调试通道（vartab）弃用**
3. **结束判据**：收到结束帧（AA 5A C9 … 5A 55）或全部 CHECK_NUM 项收齐
4. **重测**：治具"重测"键 = 重新发 0x1C/C9 触发帧（被测板 `selfcheckrestart()` 会清零所有结果）
5. **电机安全**：自检中电机实际转动（Vq 最高 4000），工装必须固定可靠；治具流程里下电前确认 MOTION_SELFCHECK 已退出
6. **周期上传与自检互斥**：自检期间 0xA9 等周期包停发，治具不要在自检中等周期包判超时
